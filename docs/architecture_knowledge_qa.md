# WenKB 架构与知识点问答记录

版本：v0.1  
建立日期：2026-09-04  
状态：持续维护

## 1. 文档目的

本文档用于记录后续围绕 WenKB 项目提出的架构问题、技术概念问题和实现理解问题。

每当用户提出相关疑问时，应先结合项目需求分析、概要设计、详细设计、数据库设计、接口设计和当前代码进行解答，再将问题与解答追加到本文档，形成可持续复习和交接的知识记录。

## 2. 适用范围

本文档记录以下类型的问题：

- 系统总体架构、分层职责和模块边界。
- 知识库、数据集、文档、索引、向量检索和问答流程。
- 数据库表结构、状态流转、数据一致性和持久化策略。
- LLM、embedding、RAG、摘要、Q&A、三元组等技术概念。
- 前后端交互、接口设计、异步任务、配置管理和部署运维。
- 阅读项目代码时产生的具体实现疑问。

## 3. 解答约定

回答问题时应遵循以下原则：

1. 先给出简明结论，再解释原因和关键概念。
2. 明确区分“项目设计目标”“当前代码实现”和“可改进方案”。
3. 涉及项目行为时，优先引用对应的设计文档、接口约定或代码位置。
4. 涉及多个概念时，说明它们之间的关系，并尽量结合 WenKB 的实际流程举例。
5. 发现设计与实现不一致时，记录差异、影响和建议，不直接把实现现状描述为设计基线。
6. 对不确定或需要进一步验证的内容，明确标记验证结论和验证方式。

## 4. 记录格式

每条问答使用以下格式，按时间顺序追加。问题较复杂时，可以拆分为多条记录。

```markdown
### Q<number>：<问题标题>

提问日期：YYYY-MM-DD
分类：架构 / 概念 / 实现 / 数据 / 接口 / 部署 / 测试
关联文档：<相关文档链接，必要时补充代码文件>

#### 问题

<完整记录用户提出的问题>

#### 简明结论

<用一至三句话回答核心问题>

#### 详细解答

<解释背景、原理、判断依据和关键流程>

#### 在 WenKB 中的对应关系

<说明该问题对应的模块、数据、接口、状态或代码实现>

#### 需要注意

<记录边界条件、常见误解、设计与实现差异或后续行动>
```

## 6. 维护要求

- 新增问答时不删除历史记录；如结论发生变化，应追加修订说明。
- 结论依赖代码行为时，应在关联文档中注明文件路径和必要的行号。
- 影响架构基线的结论，应同步检查需求分析、概要设计或详细设计文档是否需要更新。
- 修改本文档后，应同步更新 `AGENTS.md` 的维护记录，并创建对应的 Git commit。
- 文档内容发生变化后，应执行相关文档测试和链接检查。

## 7. 初始使用说明

本文档是持续积累的项目学习记录，不替代需求分析、概要设计、详细设计等基线文档。后续解答应以基线文档和实际实现为依据，并在必要时指出两者之间的差异。
